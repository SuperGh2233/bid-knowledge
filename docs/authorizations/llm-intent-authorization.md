# LLM 查询意图识别 授权记录（2026-09-16）

> 本文件在**执行任何 LLM 意图识别调用之前**写入（与 `docs/authorizations/ocr-authorization.md`
> 「在执行任何 OCR 调用之前写入」同一惯例）。

## 一、授权语句

用户 2026-09-16 在被问及「意图识别层用哪种实现」时，明确选择：**「调 LLM 做意图识别」**。
该指示由用户本人作出，且**点名了动作（调 LLM）与外发性质**（该选项的说明里写明
「把用户那句短查询发给公司网关」），构成对本次外发的有效授权。

**授权范围：**

> 允许将**用户输入的那一句检索查询文本**（如「华大转录组30万以上的合同」）
> 发送至 `.env` 配置的 LLM 网关（`https://newapi.oebiotech.com/v1`），
> 用于识别其**意图**（查合同 / 查材料事实 / 查仪器 / 查方案章节）与**实体**
> （产品 / 金额门槛 / 日期范围 / 厂商 / 仪器 / 材料类别）。

⚠️ **2026-09-16 用户追加裁定：本地优先、判不出才外发**（原话「本地有限+判断不出大模型兜底」）。
故外发**只发生在本地判不出的查询上** —— 判据是**既有解析器能否解析成功**
（`recognize_intent_local` 里 `parse_demo_query` 抛 `ValueError` 即"判不出"）。
实测代价：LLM 往返 **6.5–20 秒/句**，故绝大多数查询必须走本地（毫秒级、零外发）。

## 二、外发内容（**这是本项目迄今外发面最小的一条**）

| 项 | 内容 |
|---|---|
| 外发单元 | **用户自己敲的那一句话**（通常 10–30 字） |
| 是否含投标正文 | **否** |
| 是否含文件名/路径 | **否** |
| 是否含合同金额/甲方 | **否**（除非用户自己在查询里写了） |
| 是否含证据原文 | **否** |

对照：OCR 外发 2898 页合同原件图像；方案生成外发我方响应正文；本项只外发**一句话**。

## 三、为什么需要它（需求方实测驱动的结论）

需求方 2026-09-15/16 连续三轮在同一处踩坑，根因**不是某个词漏了，而是路由靠多份手写词表**：

| 现象 | 根因 |
|---|---|
| `测序仪` 能查、`质谱仪` 被拒 | `_FACT_KW`（路由用）与 `_UNSUPPORTED_CONDITIONS`（合同侧拦截）与 `instrument_aliases.json`（检索用）**三份表互不知道对方存在** |
| `华大转录组30w` 被拒 | 厂商名硬编码在拦截正则里 |
| 社保月份抓错 | 期间抽取的上下文判据靠手写标记表 |

**手写词表之间的漂移**是这个缺陷类的真因 —— 每修一个词，就有同类词仍掉在洞里。
意图识别把「先分类、再按类分派」交给模型，**用一句查询换掉三份必须同步维护的词表**。

## 四、安全约束（代码层，不靠约定）

- **默认关闭**：`config.INTENT_LLM_ENABLED` 默认 `false`；关闭时走**本地确定性识别**
  （现有规则仍在，作为离线/未授权路径），**不会有任何外发**。
- **只发查询句**：`recognize_intent_llm()` 的输入**只有 `query` 参数**，
  函数签名里**没有任何**能传文档正文/路径/证据的入口。
- **失败即降级**：网关不可达 / 返回非法 JSON → **回落到本地识别**并如实标注
  `source="local_fallback"`，不静默外发、不因外发失败而 500。
- **结果必须可审计**：返回 `{intent, entities, confidence, reason, source}` ——
  接入方与页面都能看到「系统理解成了什么」，与既有 `parsed` 回显同一直觉。
- 日志**不打印查询原文与 key**。

## 五、回退

`INTENT_LLM_ENABLED=false` 即完全回退到本地规则，行为与本次改动前一致。
